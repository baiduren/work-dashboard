# 00 产品概要：个人工作台

> 状态：草案（由团队维护；每次范围变更在本文件与 ADR 中同步）

## 一句话定位

一个**单人使用**的综合工作台：把日常与工作事项、任务看板、周回顾集中在一处，本地优先、无外部依赖。

## 目标用户

- 一位个人用户（本人），部署在家里的主机，经代理在公网访问；
- 单账号登录（仅本人），不做多用户、注册与权限体系。

## 核心场景

1. **今日**：今天到期、已逾期、以及无日期但今天想做的事项；
2. **收件箱**：随手记录、稍后归类；
3. **任务**：标题、备注、状态、优先级、截止日期、标签、所属项目；
4. **看板**：按状态分列（待办 / 进行中 / 完成），拖拽移动并持久化；
5. **回顾**：按周查看完成情况。

## MVP 范围（必须）

- **单用户登录（账号 + 密码）**：未登录不能访问任何页面或 API；
- 任务的创建、编辑、完成、删除（含标签与项目归属）；
- 今日、收件箱、项目列表、看板、回顾五种视图（收件箱与今日「待安排」组同源，Issue #50）；
- 看板拖拽改变状态并持久化；
- 本地数据持久化（SQLite），支持导出为 JSON；
- 快速添加（键盘优先）；
- 空库首次启动后 30 秒内可创建第一条任务并在今日视图看到。

## 非目标（v1 不做）

- 多用户、开放注册、分享与权限体系；
- OAuth / 第三方登录、单点登录；
- 移动端原生应用（先做响应式 Web）；
- 日历双向同步、第三方集成（飞书 / Notion / 邮件）；
- 通知推送、AI 自动排期；
- 云同步与多设备实时协作。

## 成功标准

- 本机一条命令启动开发环境；
- 未登录访问任何页面/API 被拒绝；登录后正常使用；退出后会话失效；
- 数据一致性：任务在今日 / 项目 / 看板三处的状态一致；
- 导出 JSON 后清库再导入，可完整恢复；
- 关键路径有自动化测试（数据层 + 至少一条端到端）。

## 开放问题

- 技术栈：已确认（[ADR-0001](adr/0001-stack.md)、[ADR-0003](adr/0003-ui-components.md)）；
- 是否需要登录：**已确认需要**——单用户账号 + 密码，公网经代理访问（[ADR-0004](adr/0004-authentication.md)）；
- 部署形态：家里的主机 + Docker 部署（[ADR-0002](adr/0002-docker-deployment.md)），前置 HTTPS 代理。
